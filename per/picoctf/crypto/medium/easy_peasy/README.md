# 問題

>Description<br>
>A one-time pad is unbreakable, but can you manage to recover the flag? (Wrap with picoCTF{})

説明<br>
ワンタイムパッドは破ることができませんが、フラグを復元できますか？（picoCTF{}で囲んでください）

# 解法要約
鍵使い回し、xor、勝ち

# 解法

配布ファイルは Pythonファイル一つ<br>
インスタンスサーバーがあるので通信すると...

```
******************Welcome to our OTP implementation!******************
This is the encrypted flag!
1ec629d4c3897442e888e0473fdde3f4bff9a28d56ce61011a8cec87be52db92

What data would you like to encrypt?
```

Pythonファイルを見ると、otpを作り出すコードが書いてある<br>
otp は用意された key と xor で暗号文を作り出している<br>
鍵の長さは 50000文字であるが、使いまわしている...

使いまわしているということはフラグの暗号化に使われた key の部分がまた 1巡してくるわけである<br>
今回の問題は key のフラグに使われた続きから暗号化をしているため、 50000文字送った時の最後の部分がフラグと xor された部分である

ということで 50000文字の 'a' を送って 'a' と暗号化された 'a' と暗号化されたフラグを xor してフラグゲット

※因みに問題の easy peasy は超簡単・朝飯前などの意

### otp (one time pad) とは
今回の問題は otp (one time pad) がテーマであった<br>
otp (one time password) とは別のものであることに注意 (以下、otp は one time pad の意で使う)

otp は鍵を使いまわさず、一回使ったら破棄する共通鍵暗号方式である<br>
otp は以下の 3つの条件を守れば完全に解読不可能と証明されている

* 鍵は完全ランダムに作成
* 鍵は暗号文と同じかそれ以上のサイズ
* 使いまわさない

完全ランダムな鍵の作成には数学的な疑似乱数生成機ではなく、自然のノイズからの抽出などの操作を行う

暗号化の操作は xor やヴィジュネル暗号などを使う

解読不可能であることは理想的である<br>
しかし、暗号文と同じサイズの鍵が必要なこと、そのサイズの鍵をあらかじめ共有する必要があることなどの運用コストが高く、鍵を安全に共有することができる状況ならそもそも暗号文を送ればいいなどの理由もあり、一般的な通信システムでは使われない

今回の問題では鍵を使いまわすことにより 3つ目の条件が破られているため解読ができた<br>
因みに、同じく鍵の使いまわしにより暗号解読されてしまったヴェノナプロジェクトの話も過去にある
