# 問題

>Description<br>
>Oracles can be your best friend, they will decrypt anything, except the flag's ciphertext. How will you break it?

説明<br>
オラクルはあなたの最高の味方となり、旗の暗号文以外なら何でも解読してくれるでしょう。さて、あなたはどうやって旗の暗号文を解読しますか？

# 解法要約
n + c = c (mod n)、勝ち

RSA の公開鍵 N, e と flag を暗号化した暗号文 c はもらえる<br>
そして、c 以外を復号してくれるオラクルも提供してくれている<br>

フラグの復号は対応していないというが...

実はこのオラクルが拒否してくるのは c だけであり、それ以外の暗号文からのフラグの復号は可能であり、c + N を送ると平文が帰ってくる<br>
どういうことかというと、RSA の復号手順は以下だ

c (暗号文), d (秘密鍵), m (平文), N (公開鍵)
$$ c^{d} \equiv m \quad (mod N) $$

このとき c に c + N を代入すると

```math
\begin{align}
(c + N)^{d} &\equiv c^d + N \cdot K \quad (mod N) \\
&\equiv c^d \quad (mod N) \\
&\equiv m \quad (mod N)
\end{align}
```

(1) の 左辺から右辺は普通に展開しているだけだが、展開後の項のうち $ c^d $ 以外の項は N の倍数になる<br>
つまり、K を適当な整数として $ N \cdot K $ で表すことができる<br>
(1) -> (2) は mod N であるため成り立つ<br>
(2) -> (3) は先に書いた式変形である

よって、c と c + N は復号した時に同じ平文となる

今回の問題のオラクルは c + N に対して対策を施していないため、 c + N をサーバーに送り平文が帰ってきてフラグゲット

### 他の解法 (選択暗号文攻撃 とパディング)
今回は c + N で通ったが、恐らく問題の想定解は選択暗号文攻撃である<br>
というのも、タイトルの no padding no problem は選択暗号文攻撃を前提とした話だからである

さて、選択暗号文攻撃とは何か<br>
選択暗号文攻撃というのは暗号文を攻撃者が自由に選び、復号を行うことができ、そこを足掛かりに攻撃対象の暗号文の復号を行う攻撃である

選択暗号文攻撃はオラクルを使う前に攻撃対象の暗号文が得られるか得られないかで分けられ、それぞれ CCA2, CCA1 という<br>
基本的に CCA2 の状態の方が危険であるから暗号は CCA2 に耐えられることを目指す

実際にこの問題で考える<br>
あるランダムな整数 t (1 < t < N) を e 乗して c を掛けたものを復号してもらうことを考える
```math
\begin{align}
(c \cdot t^e)^d &\equiv c^d \cdot (t^e)^d \quad (mod \; N) \\
&\equiv c^d \cdot t^{ed}\quad (mod \; N) \\
&\equiv m \cdot t \quad (mod \; N) \\

m \cdot t \cdot t^{-1} &\equiv m \quad (mod \; N)

\end{align}
```
復号してオラクルから帰ってくる値は (6) である<br>
そこから t の逆元 ($ t^{-1} $) を掛けて m を取り出しているのが (7) 式である

これで、選択暗号文攻撃により c を復号してもらう必要もなく m を得ることができたのでこの問題は終了である

が、これはパディングを施すことにより対策されてしまう

パディングとは、ある厳格なルールに則ったバイト列などを数字の前に付加することである<br>
そのルールはいろんな規格があり、rsa のメジャーなパディング方式として PKCS #1 v1.5 が挙げられる

PKCS #1 v1.5 は数字 M に対して以下のようにパディングを施す
```
EM = 0x00 || 0x02 || PS || 0x00 || M

PS: pseudo-randomly generated nonzero octets
```

このパディング方式を施すと、オラクルが復号した時に結果の数をこのルールを満たしているかを判定する

まず、結果の数を既に決められた固定の長さのバイト列と見なす<br>
このとき足りない分は前に 00 を付け加えていく<br>
最初のバイト列が 00 02 であり、その後に 00 が登場するかを判定し、その基準を満たさない結果はエラーと見なして何も結果を返さないとする

これをすることにより、(6)式の $m \cdot t$ はほとんどの確率でこのルールを満たさない<br>
結果、適当な t ではオラクルがエラーという情報しか吐かず、選択暗号文攻撃ができなくなる

※因みに PKCS #1 v1.5 では 100万個の選択暗号文を送ることにより m を取り出せてしまう
