# Writeup: i like peppers. (picoCTF)

## 問題概要
配布された `chall.py` は、AES暗号の構造を模倣した暗号化スクリプトです。しかし、重要な非線形変換である `sub_bytes` 関数や `sub_word` 関数が空（何もしない）になっており、暗号化プロセス全体が線形変換の組み合わせになっています。

## 解析
1. **線形性の特定**:
   AESの暗号化プロセスにおいて、S-box（`sub_bytes`）が欠落しているため、暗号化関数 `AES(plaintext, key)` は、鍵 `key` と平文 `plaintext` に対して線形な写像となります。
   具体的には、`AES(pt, key) = M(key) * pt + C(key)` または `AES(pt, key) = A(pt) * key + B(pt)` のような線形関係が成り立ちます。

2. **鍵の特定**:
   既知の平文 `pt1` とその暗号文 `ct1` が与えられています。
   `AES(pt1, key) = A(pt1) * key + B(pt1) = ct1`
   この式において、`A(pt1)` は128x128の行列、`B(pt1)` は128ビットのベクトルとして表現できます。
   `key` の各ビットを未知数として、GF(2)上の連立一次方程式をガウスの消去法で解くことで、鍵 `key` を特定しました。

3. **フラグの復号**:
   鍵 `key` が特定できたため、同様にフラグの暗号文 `ct_flag` からフラグ `flag` を復号します。
   `AES(flag, key) = M(key) * flag + C(key) = ct_flag`
   ここでも、`M(key)` を行列として構築し、連立一次方程式を解くことで、元のフラグ `flag` を導出しました。

## 結論
暗号アルゴリズムから非線形性を排除すると、線形代数的な手法（連立一次方程式の解法）によって容易に解読可能になるという脆弱性を突く問題でした。

フラグ: `picoCTF{spi1cy!}`
